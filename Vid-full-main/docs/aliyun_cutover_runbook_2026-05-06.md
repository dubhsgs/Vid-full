# VAID Aliyun Cutover Runbook

Date: 2026-05-06

Status: ready for server-side execution. This document does not change UI code.

## Current facts

- Current public domain: `vaid.top`
- Current DNS at Aliyun:
- `@ -> A -> 75.2.60.5`
- `www -> A -> 75.2.60.5`
- `75.2.60.5` is the current Netlify-side entry IP, not the Aliyun server
- Current Aliyun mainland server public IP: `47.93.232.20`
- Local frontend build verified on 2026-05-06 with `npm run build`
- Frontend is a static Vite site and can be served directly by Nginx

## Non-negotiable constraint

- Do not change the current VAID UI during infrastructure migration unless explicitly approved in advance.

## Goal

Move the public website for `vaid.top` and `www.vaid.top` from the old Netlify path to the Aliyun mainland server, while preserving the existing frontend UI and keeping Supabase/Auth/Alipay flows working under the same production origin.

## Local prep completed

- Production build output exists in `dist/`
- SPA routing confirmed:
- `/`
- `/card-generator`
- `/verify/:id`
- `/privacy`
- `/terms`
- `/payment-success`
- Nginx needs HTML5 history fallback to `/index.html`

## Before touching DNS

1. Confirm Supabase Auth redirect URLs include:
- `https://vaid.top`
- `https://vaid.top/*`
- `https://www.vaid.top`
- `https://www.vaid.top/*`
- local dev URLs if still needed

2. Confirm Supabase function secrets:
- `SITE_URL=https://vaid.top`
- `PUBLIC_SITE_URL=https://vaid.top`

3. Keep Netlify online until Aliyun smoke tests pass after DNS switch.

## Server target layout

- Web root: `/srv/www/vaid.top/current`
- Optional ACME challenge root: `/var/www/certbot`
- Nginx site config: `/etc/nginx/conf.d/vaid.top.conf`

## Server commands

Run on the Aliyun server as a sudo-capable user:

```bash
sudo dnf install -y nginx
sudo mkdir -p /srv/www/vaid.top/current
sudo mkdir -p /var/www/certbot
sudo systemctl enable nginx
```

Upload local `dist/` contents to:

```bash
/srv/www/vaid.top/current
```

The deployed root must contain `index.html` directly under `current/`, not `current/dist/`.

## Nginx config

Prepared file:

- [ops/nginx/vaid.top.conf](/Users/yan/Documents/VAID/Vid-full-main/ops/nginx/vaid.top.conf)

Behavior:

- Redirect HTTP to HTTPS
- Redirect `www.vaid.top` to canonical `https://vaid.top`
- Serve static build from `/srv/www/vaid.top/current`
- Use `try_files` fallback for React Router
- Apply the same core security headers currently defined in `vercel.json`

Install it on the server:

```bash
sudo cp /path/to/vaid.top.conf /etc/nginx/conf.d/vaid.top.conf
sudo nginx -t
sudo systemctl reload nginx
```

## HTTPS

Two practical options:

1. Alibaba Cloud SSL certificate
- Issue/bind a certificate for `vaid.top` and `www.vaid.top`
- Update the `ssl_certificate` and `ssl_certificate_key` paths if they differ from the sample config

2. Certbot / Let's Encrypt
- Use the sample config's ACME challenge location
- Issue a cert before turning on the 443 server blocks, or temporarily serve HTTP-only until the certificate is issued

If using Certbot, one common flow is:

```bash
sudo dnf install -y certbot
sudo certbot certonly --webroot -w /var/www/certbot -d vaid.top -d www.vaid.top
```

Then test and reload Nginx again.

## Smoke test before DNS switch

Once files and Nginx are in place on `47.93.232.20`:

1. Open `http://47.93.232.20`
2. Confirm the existing VAID homepage UI renders correctly
3. Confirm static assets load
4. Confirm a deep route works through Nginx fallback:
- `http://47.93.232.20/verify/test`
5. Confirm no UI regressions were introduced by infra changes

If HTTPS is already configured, also test:

1. `https://47.93.232.20` is not required
2. `https://vaid.top` should only be tested after DNS cutover because certificate/domain matching matters

## DNS cutover

At Aliyun DNS:

1. Lower TTL for `@` and `www` before cutover if operationally possible
2. Change:
- `@ -> A -> 47.93.232.20`
- `www -> A -> 47.93.232.20`
3. Keep the old Netlify deployment untouched during propagation

## Post-cutover checks

After DNS has begun resolving to `47.93.232.20`:

1. Open `https://vaid.top`
2. Open `https://www.vaid.top` and confirm it redirects to apex
3. Check homepage, verify page, payment success page, privacy, terms
4. Check login flow
5. Check Supabase reads/writes from the browser
6. Check Alipay order creation still uses the correct origin
7. Confirm QR links generated by the site now point to `https://vaid.top/verify/...`

Useful checks:

```bash
curl -I http://vaid.top
curl -I https://vaid.top
curl -I https://www.vaid.top
```

Expected result after cutover:

- Response should come from Nginx on Aliyun, not from the old Netlify path

## Rollback

If cutover fails:

1. Revert DNS:
- `@ -> A -> 75.2.60.5`
- `www -> A -> 75.2.60.5`
2. Leave the Aliyun server in place for debugging
3. Do not delete Netlify until the Aliyun path is verified stable

## What this migration does not solve

- Supabase services still remain outside mainland China
- This runbook only migrates the website hosting layer from Netlify to Aliyun
- If future compliance requires mainland replacement for database/auth/object storage, that is a separate project
